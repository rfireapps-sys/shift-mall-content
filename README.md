# shift-mall-content

シフトモール(アプリ)が起動時に読みに行く、商品カタログとお知らせの置き場です。**公開リポジトリ**なので、ここに書いた内容は誰でも読めます(ユーザーのデータや鍵は置かないこと)。

## ブランチ

- `main` … 本番アプリ(prod)が読む。**直接は編集しない。** `staging` で確認したものを取り込むだけにする(両方を編集すると、自動生成する `products.json` が食い違って、取り込みが衝突する)
- `staging` … テスト版アプリ(stg)が読む。編集は必ずここから

## 商品(`products/` フォルダ。1商品=1ファイル)

アプリが読むのは `products.json` ですが、**これは自動で作られるファイルなので、手で編集しない。** 商品を変えたいときは、`products/` の中のファイルを触る。

| やりたいこと | やること |
|---|---|
| 商品を追加する | `products/p022.json` のように、新しいファイルを作る(ファイル名は `id` と同じにする) |
| 商品を変更する | そのファイルを編集する |
| 商品の取り扱いをやめる | ファイルは消さずに `"hidden": true` を足す(下の説明を参照) |
| 商品を削除する | そのファイルを削除する(買った人の購入履歴からも画像とリンクが消える。ふつうは `hidden` を使う) |

ほかの商品のファイルは触らないので、「1件足したつもりで全員の商品が消えた」ということは起きない。

### 1商品のファイルの書き方

```json
{
  "id": "p022",
  "name": "商品名",
  "category": "家電",
  "price": 12800,
  "emoji": "🎧",
  "originalPrice": 15800,
  "badge": "SALE",
  "soldCount": 128,
  "description": "商品の説明",
  "imageUrl": "https://shift-mall.com/images/p022.png",
  "externalUrl": "https://shift-mall.com/p022"
}
```

- **必須:** `id` `name` `category` `price`
- `price` は0より大きい数値。`originalPrice`(セール前の価格)を付けるなら、`price` より大きくする
- `id` は英数字と `-` `_` だけ。ファイル名(`p022.json`)と同じにする
- `emoji` … 画像が無いときに表示する絵文字
- `imageUrl` … `https://` で始まる画像のURL、またはアプリに同梱した画像(`assets/products/...`)。空なら絵文字を表示する。アプリは切り抜かずに全体を表示する
- `externalUrl` … 購入履歴の「販売ページを見る」ボタンの行き先。`https://` だけ使える
- `imageUrl` と `externalUrl` の `https://` のURLは、**`allowed_hosts.txt` に書いた行き先だけ**使える(打ち間違いや、似せた偽サイトを防ぐため)。新しいお店やASPを使うときは、先に `allowed_hosts.txt` に1行足す
- `hidden` … `true` にすると、ショップ・カートに出なくなり、買えなくなる。買った人の購入履歴には、画像と「販売ページを見る」が残る。提携が終わってリンクを外したいときは、`externalUrl` も消す。全部の商品を `hidden` にすると、検査で止まる
- 使えない項目名を書くとエラーになる(綴りの間違いを防ぐため)
- **並び順はファイル名の昇順。** カテゴリのボタンの並びは、商品の並びで最初に出てきた順になる。新しいカテゴリは、書くだけで自動で増える

### 商品ページのURLから商品ファイルを作る(`scripts/new_product.py`)

```
python3 scripts/new_product.py <商品ページのURL> --category 家電 --emoji 🎧 --dry-run
```

- 商品名と価格を、ページに埋め込まれた商品情報(schema.org の Product、なければ Open Graph)から読む。`--dry-run` を外すと `products/` に次の番号でファイルを作る
- **価格は実際より少し高めに丸める**: 1000円以上は1000円単位、1000円未満は100円単位で切り上げ(2,400円→3,000円、350円→400円)。SALE のバッジと元の価格は付けない
- 画像と説明文はページから取らない(販売サイトの画像や文章を勝手に使わないため)。画像は絵文字で出し、ASPと提携して画像の利用が許された商品だけ、あとから `imageUrl` を足す
- URLの行き先は `allowed_hosts.txt` にあるものだけ。無ければ先に1行足す
- 価格や名前が取れないページ(大手の通販サイトに多い)は、`--price 2480`(実際の価格)や `--name` で手で渡す
- 元の商品がセール中なら、セール前の価格(メーカー希望小売価格・通常価格)を `--price` で渡す(セールが終わるたびに直さずに済むように。2026/10/28 に決定)
- 書いたファイルは公開時と同じ検査にかけ、通らなければ作らない
- 承認後にバリューコマースの商品APIなどで取れるようにするときは、`extract_from_page()` と同じ形の辞書を返す関数を足して、`main()` の取り方の分岐に足す(スクリプト冒頭の説明を参照)。APIのトークンは、このリポジトリ(公開)には置かない

### 自動で行われる検査

ファイルを `main` / `staging` に保存すると、GitHub Actions が自動で次を行う(リポジトリの「Actions」タブで結果が見られる)。

1. 全商品のファイルを検査する(`allowed_hosts.txt` が無いときも止まる)
2. 問題がなければ、`products.json` を作り直して自動でコミットする
3. **1つでも不正なら、`products.json` は更新されない**(赤い×になる)。アプリには、直前の正しい内容が配信され続ける

## お知らせ(`notices.json`)

まだ置いていない。置かない間は、アプリ同梱のお知らせを使う。置くときの書き方:

```json
{
  "global": [
    { "id": "g001", "title": "タイトル", "bodyText": "本文", "date": "2026-10-01", "isNew": true }
  ]
}
```

ファイルがあると、その内容でアプリのお知らせが**丸ごと置き換わる**(空の `[]` なら、お知らせが無くなる)。

## 運用の流れ

1. `staging` で、`products/` のファイルを追加・編集・削除する
2. 「Actions」タブで、緑の✓になっていることを確認する
3. テスト版アプリで、内容を確認する
4. 問題なければ、`staging` から `main` への Pull request を作ってマージする

反映は、ユーザーがアプリを次に開いたときです(GitHubのキャッシュで数分遅れることがある)。

## アプリ側の動き(参考)

- 取得に成功した端末は、`products.json` の内容を表示する。取得できなかった端末は、前回取得した内容、それも無ければアプリ同梱の商品を表示する
- `price` が0以下の商品は、アプリ側でも捨てられる(財布の金額を水増ししないための二重の安全策)
- `hidden` を読むのは、アプリの 2026/10/27 以降の版(blazer の #31)。それより古い版は `hidden` を無視して、ショップに出してしまう
