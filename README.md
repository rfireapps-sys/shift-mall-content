# shift-mall-content

シフトモール(アプリ)が起動時に読みに行く、商品カタログとお知らせの置き場です。**公開リポジトリ**なので、ここに書いた内容は誰でも読めます(ユーザーのデータや鍵は置かないこと)。

## ブランチ

- `main` … 本番アプリ(prod)が読む
- `staging` … テスト版アプリ(stg)が読む。先に `staging` で確認してから `main` に反映する

## ファイル

### `products.json`(通販タブの商品)

```json
{
  "products": [
    {
      "id": "p001",
      "name": "商品名",
      "category": "家電",
      "price": 12800,
      "originalPrice": 15800,
      "emoji": "🎧",
      "imageUrl": "",
      "badge": "SALE",
      "soldCount": null,
      "description": "商品の説明",
      "externalUrl": ""
    }
  ]
}
```

- `id` `name` `price` は必須。`price` は0より大きい数値。条件を満たさない商品は、アプリ側で捨てられる(1件も有効な商品が無ければ、ファイル全体が無視される)。
- **このファイルの内容が、アプリ内の商品を丸ごと置き換える。** 商品を1件足すときも、既存の商品を含めた全件を書くこと。
- `products` が空(`[]`)、またはファイルが無いときは、アプリは同梱の商品をそのまま使う。
- `imageUrl` は、画像のURL(`https://...`)。空なら絵文字(`emoji`)を表示する。
- `externalUrl` は、購入履歴の「本当に買いに行く」ボタンの行き先。

### `notices.json`(全体向けお知らせ)

```json
{
  "global": [
    { "id": "g001", "title": "タイトル", "bodyText": "本文", "date": "2026-10-01", "isNew": true }
  ]
}
```

- ファイルが無いときは、アプリ同梱のお知らせを使う。ファイルがあれば、その内容で置き換わる(空の `[]` なら、お知らせが無くなる)。

## 運用の流れ

1. `staging` ブランチのファイルを編集する。
2. テスト版アプリで、内容が出るかを確認する。
3. 問題なければ、同じ変更を `main` に反映する。

反映は、ユーザーがアプリを次に開いたときです(GitHubのキャッシュで数分遅れることがある)。
