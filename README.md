# shift-mall-content

シフトモール(アプリ)が起動時に読みに行く、商品カタログとお知らせの置き場です。**公開リポジトリ**なので、ここに書いた内容は誰でも読めます(ユーザーのデータや鍵は置かないこと)。

## ブランチ

- `main` … 本番アプリ(prod)が読む。**直接は編集しない。** `staging` で確認したものを取り込むだけにする(両方を編集すると、自動生成する `products.json` が食い違って、取り込みが衝突する)
- `staging` … テスト版アプリ(stg)が読む。編集は必ずここから

## 商品(`products/` フォルダ。1商品=1ファイル)

アプリが読むのは `products.json` ですが、**これは自動で作られるファイルなので、手で編集しない。** 商品を変えたいときは、`products/` の中のファイルを触る。

| やりたいこと | やること |
|---|---|
| 商品を追加する | `products/p022.json` のように、新しいファイルを作る(ファイル名は `id` と同じにする) |
| 商品を変更する | そのファイルを編集する |
| 商品を削除する | そのファイルを削除する |

ほかの商品のファイルは触らないので、「1件足したつもりで全員の商品が消えた」ということは起きない。

### 1商品のファイルの書き方

```json
{
  "id": "p022",
  "name": "商品名",
  "category": "家電",
  "price": 12800,
  "emoji": "🎧",
  "originalPrice": 15800,
  "badge": "SALE",
  "soldCount": 128,
  "description": "商品の説明",
  "imageUrl": "https://example.com/p022.png",
  "externalUrl": "https://example.com/p022"
}
```

- **必須:** `id` `name` `category` `price`
- `price` は0より大きい数値。`originalPrice`(セール前の価格)を付けるなら、`price` より大きくする
- `id` は英数字と `-` `_` だけ。ファイル名(`p022.json`)と同じにする
- `emoji` … 画像が無いときに表示する絵文字
- `imageUrl` … `https://` で始まる画像のURL、またはアプリに同梱した画像(`assets/products/...`)。空なら絵文字を表示する
- `externalUrl` … 購入履歴の「本当に買いに行く」ボタンの行き先。`https://` だけ使える
- 使えない項目名を書くとエラーになる(綴りの間違いを防ぐため)
- **並び順はファイル名の昇順。** カテゴリのボタンの並びは、商品の並びで最初に出てきた順になる。新しいカテゴリは、書くだけで自動で増える

### 自動で行われる検査

ファイルを `main` / `staging` に保存すると、GitHub Actions が自動で次を行う(リポジトリの「Actions」タブで結果が見られる)。

1. 全商品のファイルを検査する
2. 問題がなければ、`products.json` を作り直して自動でコミットする
3. **1つでも不正なら、`products.json` は更新されない**(赤い×になる)。アプリには、直前の正しい内容が配信され続ける

## お知らせ(`notices.json`)

まだ置いていない。置かない間は、アプリ同梱のお知らせを使う。置くときの書き方:

```json
{
  "global": [
    { "id": "g001", "title": "タイトル", "bodyText": "本文", "date": "2026-10-01", "isNew": true }
  ]
}
```

ファイルがあると、その内容でアプリのお知らせが**丸ごと置き換わる**(空の `[]` なら、お知らせが無くなる)。

## 運用の流れ

1. `staging` で、`products/` のファイルを追加・編集・削除する
2. 「Actions」タブで、緑の✓になっていることを確認する
3. テスト版アプリで、内容を確認する
4. 問題なければ、`staging` から `main` への Pull request を作ってマージする

反映は、ユーザーがアプリを次に開いたときです(GitHubのキャッシュで数分遅れることがある)。

## アプリ側の動き(参考)

- 取得に成功した端末は、`products.json` の内容を表示する。取得できなかった端末は、前回取得した内容、それも無ければアプリ同梱の商品を表示する
- `price` が0以下の商品は、アプリ側でも捨てられる(財布の金額を水増ししないための二重の安全策)
